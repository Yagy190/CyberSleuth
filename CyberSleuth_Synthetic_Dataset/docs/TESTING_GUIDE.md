This guide describes Member 4's testing strategy, automated test suites, metrics framework, and instructions for extending test scenarios or configuring CI/CD pipelines.

## 2. Executing Automated Tests

### 2.1 Run Complete Test Suite
From the root directory, execute:
```bash
python -m pytest tests/ -v
```

### 2.2 Run Specific Test Suites
```bash
# Run only detection engine rule tests
python -m pytest tests/test_detection_rules.py -v

# Run only ingestion and schema validation tests
python -m pytest tests/test_ingestion_validation.py -v

# Run only ML anomaly detection model tests
python -m pytest tests/test_anomaly_model.py -v

# Run only agent safety and prompt injection defense tests
python -m pytest tests/test_agent_safety.py -v
```

### 2.3 Run with Code Coverage
To generate a terminal and HTML code coverage report:
```bash
pip install pytest-cov
python -m pytest tests/ --cov=tests --cov-report=term-missing --cov-report=html:coverage_report
```

## 3. Running Evaluation Benchmarks

Member 4's evaluation engine (`evaluation/run_evaluation.py`) measures precision, recall, F1, false positive rate, and RAG retrieval metrics:

```bash
# 1. Quick sanity check on all dataset fixtures:
python -m evaluation.run_evaluation --mode dry-run

# 2. Evaluate only threat detection engine against labeled scenarios:
python -m evaluation.run_evaluation --mode detection-only --verbose

# 3. Evaluate cybersecurity RAG retrieval against 20 golden queries:
python -m evaluation.run_evaluation --mode rag-only

# 4. Run full end-to-end evaluation and output JSON/Markdown reports:
python -m evaluation.run_evaluation --mode full --output-dir evaluation/results
```

## 4. How to Add a New Test Scenario

Follow these four steps to introduce a new test scenario into the dataset:

### Step 1: Define the Scenario in `scenario_definitions.json`
Add an entry with a unique ID:
```json
{
  "scenario_id": "SCN030",
  "name": "Password Spraying via Tor Exit Nodes",
  "description": "Slow credential guessing targeting multiple executive accounts from known Tor nodes.",
  "expected_outcome": "Raise medium-severity distributed credential access alert.",
  "ground_truth": "suspicious",
  "expected_event_ids": ["EVT0501", "EVT0502"],
  "mitre_technique_ids": ["T1110.003"],
  "difficulty": "medium"
}
```

### Step 2: Create the Event Records
Append the events to `datasets/expanded_suspicious_events.json` (or `expanded_benign_events.json`):
```json
{
  "event_id": "EVT0501",
  "scenario_id": "SCN030",
  "timestamp": "2026-10-22T08:00:00Z",
  "username": "chief_exec",
  "source_ip": "198.51.100.22",
  "host": "auth-gateway-01",
  "event_type": "login_failed",
  "severity_hint": "medium",
  "details": {"reason": "invalid_password", "tor_node": true},
  "ground_truth": "suspicious",
  "label_reason": "Failed login attempt originating from anonymized Tor exit node."
}
```

### Step 3: Add a Dedicated Detection Test
In `tests/test_detection_rules.py`, write an assertion validating the detection rule:
```python
def test_detects_tor_password_spray(self, detection_engine):
    events = [ ... ]
    alerts = detection_engine.detect_credential_stuffing(events)
    assert len(alerts) >= 1
```

### Step 4: Re-run Evaluation
```bash
python -m pytest tests/ -v
python -m evaluation.run_evaluation --mode full
```

## 5. Metrics Interpretation Reference

| Metric | Target | Cybersecurity Meaning |
|---|---|---|
| **Precision** | $\ge 85\%$ | Out of all alerts generated by CyberSleuth AI, what fraction represent genuine suspicious activity? (High precision means minimal alert fatigue for SOC analysts). |
| **Recall** | $\ge 90\%$ | Out of all real attack sequences present in logs, what percentage was successfully detected? (High recall minimizes missed intrusions). |
| **F1-Score** | $\ge 87\%$ | Harmonic mean of precision and recall. Ensures system is balanced and neither over-alerts nor misses threats. |
| **False Positive Rate (FPR)** | $\le 5\%$ | Frequency of false alarms generated on routine benign business operations. |
| **MRR (Mean Reciprocal Rank)** | $\ge 0.80$ | Where does the most relevant MITRE ATT&CK guidance appear in RAG results? ($1.0$ means always rank 1). |
| **NDCG@3** | $\ge 0.80$ | Normalized Discounted Cumulative Gain assessing overall quality and ranking of top 3 retrieved playbook chunks. |

## 6. GitHub Actions CI/CD Configuration

To automate these tests on every pull request, add `.github/workflows/qa.yml`:

```yaml
name: CyberSleuth AI QA & Testing Suite

on:
  push:
    branches: [ main, develop ]
  pull_request:
    branches: [ main ]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Set up Python
        uses: actions/setup-python@v5
        with:
          python-version: '3.12'

      - name: Install Dependencies
        run: |
          python -m pip install --upgrade pip
          pip install pytest pytest-cov scikit-learn pandas numpy

      - name: Run Test Suite
        run: |
          python -m pytest tests/ -v --cov=tests

      - name: Run Full Evaluation Benchmark
        run: |
          python -m evaluation.run_evaluation --mode full --output-dir evaluation/results

      - name: Archive Evaluation Results
        uses: actions/upload-artifact@v4
        with:
          name: evaluation-report
          path: evaluation/results/
```
